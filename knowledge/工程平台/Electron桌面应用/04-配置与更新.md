# 配置与更新

## 一、能力范围

应用配置持久化（`electron/config-store.ts`）、开机自启、关闭行为、代理、Daemon 端口；系统托盘；应用内更新（`electron/updater.ts`）；工作区模板注入（`electron/workspace-injector.ts`）。

## 二、设计决策与取舍

- **electron-store + encryptionKey**：桌面配置单文件加密存储，名 `cursor-claw-config`（依据：config-store.ts）。
- **新旧配置共存**：`agentResources`/`channels` 新模型，旧 lark/wechat 字段仅迁移用。
- **平台差异化更新**：macOS 走 Homebrew cask；Windows 用 electron-updater；其他平台打开 GitHub Releases（依据：updater.ts）。
- **开发模式跳过更新**：除非 `FEISHU_DEV_SIMULATE_UPDATE=1` 模拟。

## 三、服务端规则

无。Daemon 端口默认 `19528`（0=随机），经 `LARK_DAEMON_PORT` 传给子进程。

## 四、客户端流程

### 工作区注入

用户触发 `workspace:inject` 或 Daemon 就绪后自动注入：

1. 全局 `~/.cursor/mcp.json` 写入 `cursor-claw`、`cursor-claw-admin` URL（`/mcp`、`/mcp-admin`）。
2. 项目 `.cursor/rules/cursor-claw.mdc`、skills 从 `resources/template/` 复制（依据：workspace-injector.ts）。

模板来源：

| 路径 | 用途 |
|---|---|
| `resources/template/rule/cursor-claw.mdc` | Loop 保活协议 Rule |
| `resources/template/skills/cursor-claw-admin/` | 自管理 Skill |
| `resources/template/workflow/` | 工作流示例 YAML |

### 更新流程

启动 4s 后 `runStartupUpdateCheck`；Settings「关于」可手动 `updater:check` / `updater:apply`。Windows 下载进度经 `updater:progress` 推送到 UI。

## 五、接口

| IPC | 说明 |
|---|---|
| `config:get/save` | 读写 AppConfig |
| `app:set-auto-start` | 同步 `app.setLoginItemSettings` |
| `workspace:inject` | 执行注入 |
| `updater:check/apply/current-version` | 更新检查与应用 |

### AppConfig 关键字段

| 字段 | 默认 | 说明 |
|---|---|---|
| workspaceDir | "" | 主工作目录 |
| daemonPort | 19528 | Daemon 期望端口 |
| closeWindowAction | ask | 关窗行为 |
| autoStart | false | 开机自启 |
| setupComplete | false | 允许自动拉起 Daemon |

## 六、数据

存储路径：`app.getPath("userData")`；profile 时为 `.../cursor-claw-{profile}/`。定时任务另存 `scheduled-tasks.json`（userData，Daemon 只读副本在 APP_DATA_DIR）。

## 七、非功能与可观测

- 托盘：显示窗口、退出（`electron/tray.ts`）；双击恢复主窗口。
- Updater 缓存：`{userData}/../Cursor Claw-updater`（getUpdaterCacheDir）。
- changelog 优先 GitHub `changelog/` 目录，fallback 内置打包目录。

## 八、推送

`updater:status`（available/downloading/downloaded）、`updater:error` 推送到渲染层。
