## 2、局限与未自动化原因

| 未自动化项 | 原因 |
|------------|------|
| F1 入队反馈 ≤3s（NF1）、Agent 现状文案 | 依赖飞书 WebSocket 与端到端时序，脚本无法稳定复现用户侧可见延迟 |
| 合并预览触发/更新/debounce（NF2、验收 4/11） | 需真实飞书 outbound 与 debounce 500ms 窗口；无 headless 通道 |
| F3 回复预览修改（验收 6–8） | 依赖飞书 `parentId` 回复链与 registry 命中，须手工在客户端操作 |
| MG-id 可见可复制（验收 5） | UI 层验收，契约脚本无法断言飞书消息卡片渲染 |
| 流式/三态协调（验收 10、NF6） | 需 SDK 长回复 + 连发观察，时序不可脚本化 |
| 超长合并分条（NF4、§八·(二)·5） | 需构造 >15KB 正文并在飞书客户端核对全文 |
| `getSessionUnclaimedCount` / replace | 纯文件队列逻辑，04 静态复核已覆盖；可选本地造 `.qmsg`/`.claimed` 目录 |
| F3 失败纠错超长（04 §3 警告 #1） | 联调超长场景时人工判定；非阻断 |
| T-FIX-01 预览 outbound 可见性 | `ensureMergePreviewSentBeforeClaim` 依赖飞书 p2p 发送与真实 sessionKey；脚本仅断言 instant poll HTTP 不 500 |
| T-FIX-02 冷启动 orphan claimed | 须全应用重启 + 磁盘预置/遗留 `.claimed`；HTTP 契约无法模拟 `initQueue` 回收 | 可选查 daemon 日志 `冷启动回收遗留 claimed→qmsg` |

## 4、场景摘要

### 4.1 飞书私聊联调 checklist（须手工验收）

| 场景 ID | 前置 | 步骤摘要 | 期望 | 关联 |
|---------|------|----------|------|------|
| **F1 忙+排队** | Agent 正在处理任务 A | 连发消息 B、C | 每条 F1 含「正在处理上一条」类表述；排队数正确 | 01·1、T4 |
| **F2 空闲** | Agent 空闲 | 连发 2 条 | 「等待 Agent 领取」/「已加入待处理队列」；**无**「正在处理上一条」 | 01·2、T4 |
| **F3 冷启动** | 该会话 Agent 未运行 | 发 1 条 | 「正在启动」+ 已排队；与三态不矛盾 | 01·3、T3 |
| **F4 合并预览** | Agent 空闲 | 连发 3 条，领取前停 | 收到 **1 次**预览；含【消息 1】～【消息 3】全文 | 01·4、T6 |
| **F5 MG-id** | 同 F4 | 复制预览中 ID | 格式 `MG-*-*`；修改确认/失败中 ID 一致 | 01·5 |
| **F6 回复修改** | 已有预览 | **回复预览消息**发新全文 | 成功确认；Agent 处理后内容为新全文 | 01·6、T7、T8 |
| **F7 引导完整** | 预览 / 故意失败 | 检查文案 | 同时含 ID、全文、「回复本条*预览*消息」操作说明 | 01·7 |
| **F8 失败纠错** | 未回复预览或空正文 | 触发失败 | 纠错含 ID + 全文 + 操作（超长见 04 §3 警告） | 01·8 |
| **F9 单条无预览** | Agent 空闲 | 仅发 1 条 | 仅有 F1，无合并预览 | 01·9 |
| **F10 流式抑制** | SDK 长回复流式进行中 | 再发 1 条 | 仅 F1；**无**新合并预览；无第二条「处理中」类通知 | 01·10、T5 |
| **F11 预览更新** | 已有 3 条预览 | 再发第 4 条 | 同一 MG-id +「已更新」+ 4 段内容 | 01·11 |
| **F12 debounce** | Agent 空闲 | 4 条间隔 &lt;1s | ≤5s 内 **1 次**预览含 4 段 | §八·(二)·3 |
| **F13 旧 preview 回复** | 预览已更新过 | 回复**首条**预览 messageId | 修改仍成功 | §八·(二)·4 |
| **F14 已领取不可改** | Agent 已领取该批 | 回复旧预览 | 「已开始处理，无法修改」类提示 | T7、F3.6 |
| **F15 重启首条** | 磁盘存在 stale `.claimed`（上轮 claim 未 ack，或手工预置 `*.claimed`）；**须全应用重启**（Electron + daemon） | 重启完成 → 飞书私聊发**首条** | F1 为「已收到，等待 Agent 领取」或冷启动「正在启动」类文案；**不得**误报「Agent 正在处理上一条」；排队数**不含** stale claimed（仅多条 unclaimed 时才有「前面还有 N 条」） | T-FIX-02、08 第 2 轮、01·2/3 |

**F15 可选观测**：daemon 启动日志含 `冷启动回收遗留 claimed→qmsg: N 条`（N≥1 时）；失败时区分未全量重启 vs 回收未生效。

**范围说明（01·12）**：上述 F4–F14 仅验收飞书私聊；微信/群聊不要求合并预览与回复修改。F1 文案增强若随 daemon 共用逻辑出现，不单独验收微信。
