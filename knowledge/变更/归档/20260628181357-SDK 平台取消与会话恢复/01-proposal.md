# SDK 平台取消与会话恢复产品需求文档

> **变更 ID**：`20260628181357-SDK 平台取消与会话恢复`
> **来源**：kb-propose
> **类型**：待确认
> **优先级**：待确认
> **外部 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 背景与问题

Cursor Claw 用户通过飞书等即时通讯通道与 Agent 对话。当 Agent 执行较长任务时，**平台侧**可能在约 7～8 分钟后主动结束本次运行（状态为取消或错误），**并非**用户点击 Stop 或发送取消指令。

**已观测现象**（同一会话连续两轮对比）：

- 上一轮长任务约 7 分钟正常结束，用户可继续对话。
- 下一轮同类长任务约 8 分钟后被平台结束；用户收到 **「Agent 任务已取消」** 类文案，易被理解为 **自己取消了任务**。
- 会话 **未能** 像超时场景那样自动回到可继续对话的空闲/长驻状态；用户往往需要额外操作才能继续同一会话。

本变更与已归档提案 **「Agent Run 超时自动停止」** 同属 **长时运行结束后的收尾与恢复** 范畴。该归档变更仍有未闭合项（评审 R1/R2）：部分平台结束路径未走完整超时收尾，且存在将 **非超时类错误** 误判为超时的风险。本 PRD 聚焦 **平台主动取消/错误** 与 **用户主动取消** 的区分，以及 **超时类收尾（文案 + 会话恢复）** 的补全与收紧。

## 目标用户与场景

### 目标用户

- **IM 通道日常用户**：通过飞书与 Agent 交互，期望长任务结束后能直接发下一条消息。
- **长任务 / kb-admin 编排使用者**：单次 Run 常达数分钟，更容易触及平台侧运行上限。

### 场景 A：平台侧长时间运行后自动结束（核心）

用户发送复杂请求，Agent 开始处理并展示进度。约 7～8 分钟后，**平台**结束本次运行（非用户 Stop）。用户期望：

- 收到 **等待超时/运行已结束** 类友好说明（语义含：本次处理因等待超时而退出、可重新发送消息继续），**而非**「任务已取消」等易被理解为 **用户取消** 的文案。
- 会话自动回到 **空闲或可继续长驻** 状态，用户 **无需** Stop、Reset 等手动恢复即可发送下一条消息。

**现状**：文案误导为「用户取消」；会话恢复不完整，影响后续对话。

### 场景 B：用户主动 Stop（须保持既有行为）

用户主动点击 Stop 或等价取消操作。用户期望：静默结束，**不** 收到失败/超时类推送，**不** 触发崩溃分析类归档。

**现状**：本变更 **不得** 改变该路径；验收须回归确认。

### 场景 C：非超时类失败（须与超时区分）

工具失败、权限拒绝、网络异常等 **非** 平台长时间等待导致的结束。用户期望：沿用既有失败处理与文案，**不** 误用「等待超时已退出」类专用提示，**不** 误走超时专用会话清理逻辑。

**现状**：部分错误结束可能被误判为超时，与归档变更 R2 所述风险一致；本变更须 **收紧** 判定，避免误伤。

### 场景 D：超时类收尾但用户未收到 IM 提示

在应走「等待超时」收尾的路径上，系统内部可能已尝试结束 Run，但用户 **未** 在 IM 通道看到对应友好提示，仅感知任务静默结束或状态异常。

**现状**：超时类用户可见通知 **不可靠**；本变更要求该类提示 **可达**（与 F2 一并验收）。

## 功能需求

### F1 区分平台结束与用户主动取消

- 当运行因 **平台侧** 长时间等待或等价策略结束（非用户主动 Stop）时，**不得** 向用户展示「Agent 任务已取消」或同等 **暗示用户取消** 的文案。
- 用户 **主动** Stop 的路径：保持 **不推送** 取消/失败/超时类 IM 通知，**不** 因本变更新增归档或告警行为。

### F2 平台长时间结束走超时类收尾

- 平台侧约 7～8 分钟非用户 abort 导致的取消或错误结束，须按 **等待超时** 类产品语义收尾：
  - 发送 **一条** 简体中文友好提示，语义包含：**会话/本次处理因等待超时已退出**、**可重新发送消息继续**（具体措辞可在设计阶段微调，须与「用户取消」文案可区分）。
  - 会话自动恢复为 **空闲**；长驻会话须恢复为 **可继续接收下一条消息** 的状态，用户 **无需** 手动 Reset。
- 收尾后 IM 侧「处理中 / 进行中」类展示须同步结束。

### F3 超时类 IM 通知可达

- 在 F2 适用的结束路径上，用户 **必须** 能在 IM 通道收到 F2 规定的友好提示（若产品启用该提示）；**不得** 出现仅内部收尾、用户侧无任何说明的情况。
- 同一结束事件 **不超过一条** 同义用户可见通知；禁止堆栈、内部错误码等技术内容。

### F4 收紧非超时误判

- **非** 平台长时间等待导致的 ERROR/过期类结束，**不得** 误用 F2 超时专用文案，**不得** 误触发超时专用会话清理（与归档变更「Agent Run 超时自动停止」评审 R2 对齐）。
- 用户主动 Stop **不得** 误走 F2/F3 超时收尾。

### F5 用户可见发布

- 本变更对用户可见（IM 文案与会话恢复行为），归档发布时须 **bump patch 版本** 并新增 **changelog** 条目，说明长时运行结束后的提示与会话恢复改进。

## 边界与不在范围

- **调整平台 7～8 分钟上限本身**：不在本变更范围；本变更解决的是 **上限触发后** 的产品行为。
- **保活等待阶段文案**：会话空闲保活超时沿用既有或并行变更逻辑；本 PRD 不重新定义保活策略。
- **非 IM 入口**：优先保证飞书等 IM 调度路径；其他入口是否对齐在设计阶段评估。
- **归档变更 R1（非长驻模式 session 清理）**：若实现与本 PRD 交叉，设计阶段须显式追溯；本 PRD 不重复定义非长驻专用策略，但 **不得** 因补全平台取消路径而加剧 R1 债务。
- **新增设置页或视觉改版**：无；Figma：无。
- **技术实现细节**：本阶段不限定模块、函数或事件顺序；设计阶段展开。

## 验收标准

1. **平台长时间结束文案**：在可复现的平台约 7～8 分钟结束场景下（同会话长任务或测试模拟），用户 IM 收到 **等待超时已退出、可重发消息** 类提示，**不出现**「Agent 任务已取消」或同等用户取消语义。
2. **会话可继续（核心）**：上述场景结束后，用户 **不执行** Stop/Reset，在同一会话发送新消息，新 Run **正常启动** 并产生回复（或明确的非超时类失败，但 **不** 被上一轮残留状态阻塞）。
3. **长驻可继续**：长驻会话在平台长时间结束后，仍可直接接收下一条用户消息，**无需** 手动重建会话。
4. **超时类通知可达**：F2 适用路径上，用户 **能收到** F2 规定的一条友好提示；同一事件 **不超过一条**；无技术堆栈或内部错误码外露。
5. **用户主动 Stop 无回归**：用户主动 Stop 后仍 **无** IM 失败/超时/取消类通知，**无** 新增崩溃归档；行为与变更前一致。
6. **非超时失败无回归**：任选非超时失败用例（如工具失败），**不** 出现 F2 超时专用文案，**不** 误清理会话；与归档 R2 验收一致。
7. **发布物**：归档时 `package.json` patch 已 bump，且 `changelog/` 存在对应版本条目，描述用户可感知的提示与会话恢复改进。
