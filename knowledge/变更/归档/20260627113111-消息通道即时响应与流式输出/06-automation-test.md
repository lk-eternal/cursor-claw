## 2、局限与未自动化原因

| 未自动化项 | 原因 |
|------------|------|
| 入队确认 ≤3s（NF1）、排队计数 | 依赖真实飞书 WebSocket / 微信长轮询与端到端延迟，脚本无法稳定复现通道侧可见时间 |
| 微信 typing 5s 内消失（NF3）、飞书 Get/DONE | 需客户端 UI 观察；无 headless 契约 |
| 流式首段 ≤10s（NF2）、PATCH POC | 依赖 SDK Agent 产出时序与飞书 API 限流；双层节流（SDK 400ms + daemon 500–1500ms）可能抬高首段延迟 |
| `getSessionPendingCount` 边界 | 纯文件队列逻辑，04 静态复核已覆盖；可选本地造 `.qmsg`/`.claimed` 文件目验证 |
| SDK `stream-text final` 队列 ack | `agent-sdk` 未传 inbound `message_id`（04 §7 债务）；联调须确认 `.claimed` 是否由后续 `send_text(message_id)` 清理 |
| `auto_test/` 冒烟脚本 | 本期未新增；通道验收以手工清单为主 |

## 4、场景摘要

| 场景 ID | 前置 | 步骤摘要 | 期望 | 关联 |

| **M4 三态 E2E** | Agent 已运行 | ≥5 次成功任务 | 已收到→处理中→完成；无 tool/路径泄露 | 01·4 |
| **M5 微信 typing** | 微信私聊 | 处理中看「正在输入」；完成后计时 | 处理中可见；完成后 ≤10s（验收 5）/ ≤5s（NF3）消失 | 01·5、T2、T8 |
