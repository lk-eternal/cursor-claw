# 飞书临时会话工作目录可选产品需求文档

> **变更 ID**：`20260627132014-飞书临时会话工作目录可选`
> **来源**：kb-propose
> **类型**：待确认
> **优先级**：待确认
> **飞书 PRD**：无
> **Figma 设计图**：无
> **任务记录**：无

## 背景与问题

飞书管理员可通过创建临时会话的方式，为单次任务开启独立对话上下文：用户描述任务后，系统切换活跃会话至该临时会话，任务结束后自动回到主会话。该机制便于并行处理不同主题，且与主会话在消息路由、会话切换、结束回退等行为上已稳定运行。

当前限制在于：**临时会话的工作目录始终与主会话相同**。当用户希望临时任务在另一项目目录下执行（例如主会话面向日常运维仓库，临时任务需要在另一个产品仓库中改代码）时，只能先切换主会话工作目录再创建临时会话，或接受 Agent 在错误目录下操作。前者会干扰主会话上下文，后者影响任务正确性与用户信任。

因此需要在**不改变现有临时会话创建、切换、回退等核心行为**的前提下，为创建临时会话增加可选的工作目录指定能力。

## 目标与非目标

### 目标

1. **可选指定工作目录**：创建飞书临时会话时，用户可额外指定该临时会话使用的工作目录。
2. **合理默认值**：未指定工作目录时，临时会话的工作目录与**当前主会话工作目录**一致，与现有行为保持兼容。
3. **创建反馈可感知**：临时会话创建成功后，向用户明确展示本次会话所使用的工作目录，便于确认是否选错。
4. **非法输入友好处理**：当指定目录无效（不存在、不可访问、不符合规范等）时，给出清晰提示，**不创建**临时会话，活跃会话保持不变。
5. **行为边界不变**：临时会话的创建入口、活跃路由切换、任务结束后的自动回退、身份与模型策略等既有规则保持不变；仅扩展「工作目录」这一维度的可配置性。

### 非目标

- **不改动**群聊、他人私聊等场景的目录隔离规则（仍使用各自既有临时/隔离目录策略）。
- **不改动**桌面端 Settings 中主工作目录的配置界面（除非用户后续单独提出；本需求未涉及）。
- **不引入**临时会话创建后的目录热切换（创建时指定即可，运行中改目录不在本期范围）。
- **不扩展**到非飞书通道（微信等）的临时会话能力，除非产品后续统一规划。
- **不改变**主会话 `/workspace` 类指令的既有语义；本需求聚焦「创建临时会话时」的目录选择。

## 用户与场景

### 用户

- **飞书管理员**（具备创建临时会话权限的用户）：主要操作者，在飞书私聊中发起临时任务。

### 场景 A：默认目录（与现网一致）

管理员创建临时会话时仅提供任务描述，不指定工作目录。系统使用当前主会话工作目录；创建成功反馈中展示该目录；临时会话内 Agent 行为与现网一致。

### 场景 B：指定其他项目目录

管理员创建临时会话时，在任务描述之外指定一个有效的工作目录（例如另一个本地项目路径）。临时会话在该目录下运行；主会话工作目录与活跃路由逻辑不受影响；任务结束后仍回退至创建前的主会话。

### 场景 C：指定无效目录

管理员指定了不存在或无权限访问的目录。系统返回友好错误说明（含失败原因的用户可理解表述），**不创建**临时会话，当前活跃会话不变，用户可修正后重试。

### 场景 D：主会话目录已切换后的临时任务

管理员此前已通过主会话相关能力将主工作目录切换为项目 B，再创建未指定目录的临时会话。临时会话默认使用项目 B（即当时的主会话目录），而非历史默认值，确保「默认 = 当前主会话」语义一致。

### 场景 E：连续创建多个临时会话

管理员先后创建多个临时会话，分别使用不同目录或均使用默认。每个临时会话独立绑定创建时所确定的工作目录；结束与回退行为仍按既有临时会话规则执行，互不串扰。

## 现状简述

- 飞书管理员通过创建临时会话指令（含任务描述）开启 `temp` 类型会话；创建后系统切换活跃路由至该临时会话，结束后自动回退主会话。
- **临时会话当前固定使用主目录作为工作目录**，无法针对单次临时任务单独指定。
- 主用户私聊会话使用通道或全局配置的主工作目录；用户可通过查看/切换主会话工作目录的相关指令了解当前主目录位置。
- 群聊与他人会话使用隔离的临时工作目录策略，与本需求无关。
- 工作流场景中已存在「按节点指定工作目录」的类似产品能力，可作为「同类需求已在其他场景落地」的参考，但临时会话侧尚未提供等价选项。

## 功能需求

### 1. 创建时可选工作目录

| 编号 | 需求描述 |
|------|----------|
| F1.1 | 创建飞书临时会话时，除任务描述外，用户**可选**提供工作目录。 |
| F1.2 | **未提供**工作目录时，临时会话工作目录等于**创建时刻**主会话的工作目录（与现网默认行为一致）。 |
| F1.3 | **已提供**且校验通过的工作目录，仅绑定于该次创建的临时会话，不影响主会话及其他会话的目录。 |
| F1.4 | 目录指定为**创建时一次性**确定；临时会话运行期间不支持通过本需求变更目录（改目录非本期目标）。 |

### 2. 目录校验与失败处理

| 编号 | 需求描述 |
|------|----------|
| F2.1 | 创建前须校验用户提供的工作目录：路径存在、可访问、符合系统允许使用的目录范围。 |
| F2.2 | 校验失败时，向用户返回**简短、非技术化**的错误说明（例如「目录不存在」「无法访问该目录」），并建议检查路径或改用默认。 |
| F2.3 | 校验失败时**不得**创建临时会话、**不得**切换活跃路由。 |
| F2.4 | 未指定目录时，沿用现有主会话目录解析逻辑；若主会话目录本身不可用，按既有主会话错误规范处理（本需求不新增独立分支，但不得因本特性导致静默失败）。 |

### 3. 创建成功反馈

| 编号 | 需求描述 |
|------|----------|
| F3.1 | 临时会话创建成功后，反馈中须包含：**任务摘要**（或等价确认信息）、**本会话使用的工作目录**、**会话标识**（用户可识别的临时会话名称或编号，沿用现有展示习惯）。 |
| F3.2 | 使用默认目录时，反馈中仍须**显式展示**所采用的目录路径，避免用户误以为沿用了历史或其他会话的目录。 |
| F3.3 | 反馈文案使用简体中文，路径展示清晰可读；不要求用户理解内部会话类型等技术概念。 |

### 4. 与既有临时会话行为的一致性

| 编号 | 需求描述 |
|------|----------|
| F4.1 | 指定目录与否，均不改变：创建权限判定、活跃会话切换时机、临时会话结束后的主会话回退、消息路由至当前活跃会话的规则。 |
| F4.2 | 临时会话内的 Agent 身份注入、模型选择、resume 策略等既有产品规则保持不变。 |
| F4.3 | 同一管理员在主会话与多个临时会话之间切换时，各会话绑定的工作目录在各自生命周期内保持稳定。 |

### 5. 主会话工作目录关系

| 编号 | 需求描述 |
|------|----------|
| F5.1 | 创建临时会话**之后**，用户若通过主会话能力修改主工作目录，**不 retroactive** 影响已创建且仍在运行的临时会话目录。 |
| F5.2 | 临时会话结束后回退的主会话，其工作目录以回退时刻主会话实际目录为准，与临时会话曾使用的目录无强制联动。 |

## 交互与体验

### 创建入口（产品层）

在现有「创建临时会话 + 任务描述」交互基础上，**扩展可选参数**，使用户能在同一条创建操作中附带工作目录。产品层表达示例（非实现语法）：

- **仅任务**：「创建临时会话，任务：修复登录页样式」→ 使用当前主会话目录。
- **任务 + 目录**：「创建临时会话，任务：修复登录页样式，工作目录：某某项目文件夹」→ 使用指定目录。

具体参数名称、顺序、分隔方式在设计与实现阶段确定；产品要求：**单条消息内可完成创建**，无需先切换主目录再创建；**帮助/说明文案**中须告知可选目录及默认规则。

### 默认与提示

- 帮助或指令说明中明确：**省略目录 = 使用当前主会话工作目录**。
- 用户可通过既有「查看主会话工作目录」能力确认默认值，再决定是否显式指定。
- 不建议在创建成功反馈中仅写「默认目录」而不给出具体路径。

### 错误体验

- 无效目录：一条消息说清问题 + 可操作下一步（检查路径 / 省略目录重试），不出现堆栈、内部错误码或系统路径以外的敏感信息。
- 创建失败时用户应仍能继续在主会话或已有临时会话中正常发消息。

### 与主会话目录指令的关系

- 主会话的工作目录查看与切换能力保持独立；本特性不替代、不合并该能力。
- 用户心智模型：**主会话目录**管默认与主对话；**创建临时会话时的可选目录**管单次临时任务 override。

## 兼容性

| 维度 | 要求 |
|------|------|
| 未指定目录的创建方式 | 与现网行为一致，现有用户无需改变操作习惯 |
| 已存在的临时会话 | 本需求上线前已创建的会话不受影响；新规则仅作用于新创建 |
| 飞书通道其他能力 | 入队、回复、指令体系、会话列表展示等不因本需求产生回归 |
| 非飞书通道 | 不在本期范围，行为保持不变 |
| 群聊 / 他人会话 | 目录规则不变，不开放本需求的可选目录能力 |

## 验收标准

1. **默认目录**：主会话工作目录为已知路径 A 时，不指定目录创建临时会话，创建成功反馈中展示的路径为 A；该临时会话内执行需感知工作目录的任务时，行为与在目录 A 下运行一致（可通过用户可观察的任务结果验证，如列出/修改该目录下已知内容）。
2. **指定有效目录**：指定有效路径 B（B ≠ 当前主会话目录）创建临时会话，反馈展示 B；临时会话任务在 B 语境下生效，主会话目录仍为 A；临时会话结束后活跃会话回退主会话，主会话目录仍为 A。
3. **无效目录**：指定不存在或不可访问目录时，**不创建**临时会话，活跃会话不变，用户收到明确错误提示；连续重试合法参数后可成功创建。
4. **创建反馈完整性**：至少 3 次成功创建（含默认 1 次、指定 2 次不同路径），反馈均包含任务确认信息与**完整展示**的工作目录路径。
5. **行为无回归**：指定目录与否，临时会话的切换、在临时会话内对话、结束回退主会话等流程与现网一致，无额外异常步骤或丢失回退。
6. **边界隔离**：群聊与他人私聊场景**不**出现本需求的可选目录入口或行为变化；桌面端 Settings 主工作目录配置**无**因本需求产生的 UI 或文案变更（除非后续单独立项）。
7. **并发与顺序**：连续创建两个临时会话并分别指定不同目录，各自目录绑定正确，结束顺序与回退行为符合既有临时会话规则，无目录串用。
8. **文档与帮助**：面向管理员的使用说明或内置帮助中，可查到「可选工作目录、默认等于主会话目录、无效则不创建」三条要点。
