# 工作流 · 触发与管理入口

## 一、能力范围

创建定义、启动实例、查询状态：设置页、`/workflow` 指令、`manage_workflows` MCP。不负责 Agent 侧 next/reject。

## 二、设计决策与取舍

- UI、指令、MCP `run` 均 `createInstance`+`startWorkflow`+`launchWorkflowAgent`（MCP 另 emit stdout 信号）。
- `notifyChatId`：指令=触发者 chatId；UI=主用户通道 chatKey。
- 定义 CRUD 在 admin MCP；流转在 agent MCP（`daemon.ts`）。

## 三、服务端规则

**manage_workflows**：list/get/create/update/delete/run/status。`create/update` 解析 YAML/JSON；`run` 建实例并 `__WF_LAUNCH__`。

## 四、客户端流程

`Settings`→tab「工作流」→`WorkflowPanel`：定义（编辑/启动/删）、实例（列表/详情/删）。飞书管理员 `/workflow ls|info|run|status|delete`。

```mermaid
flowchart LR
  U[用户] --> S[设置页]
  U --> F[/workflow]
  U --> AI[Admin MCP]
  S --> WR[workflow-runner]
  F --> WR
  AI --> ENG[engine]
```

## 五、接口

| 子命令 | 说明 |
|--------|------|
| ls, info \<id\> | 列/查定义 |
| run \<id\> [输入] | 启动 |
| status [实例ID] | 查实例 |
| delete \<id\> | 删定义 |

MCP action 见上；IPC `workflow:run` 等。

## 六、数据

读写 `workflows/definitions` 与 `instances`，无额外存储。

## 七、非功能与可观测

指令经 `reportCommandResult`；MCP 错误文本返回。

## 八、推送

run 成功通知 `notifyChatId`（UI 主用户/指令操作者）。

## 九、已知限制与 TODO

- `/workflow` 无 create/update；paused 无 UI 恢复。
- MCP create 文案写 JSON，实际支持 YAML。
