# 消息队列与路由

## 一、能力范围

file-queue、sessionKey、ack、F1、**MergeBatch**、**Daemon dispatch**、Presentation/stream 出站、SSE。

**不负责**：SDK Run 内部、CardKit 渲染（见 [02](./02-飞书通道.md)）。

## 二、设计决策与取舍

- 原子入队；`.qmsg→.claimed`。
- **冷启动 orphan 回收**：`initQueue` 调用 `cleanupOrphanClaimedOnColdStart`（`file-queue.ts`），全应用重启后将遗留 `.claimed` 还原为 `.qmsg`，保留「至少一次」投递；异常双份时删 claimed 保留已有 `.qmsg`。
- **T7 编排**：SSE/入队 → `scheduleAgentDispatch`(300ms) → `runAgentDispatchLoop` → agent-api；**无 poll**。
- **MergeBatch**：≥2 collecting → 静默 → ready → `performClaimAndMerge`。
- **M7**：processing 或 collecting 静默期 `shouldDeferDispatch`。

## 三、服务端规则

- F1：`shouldSendEnqueueF1` suppress collecting 第 2+ 条；排队数仅 `getSessionUnclaimedCount`（`.qmsg`），**不含** orphan `.claimed`；`buildEnqueueStatusText` 在 `phase` 缺失时默认 `idle`，不用磁盘 `.claimed` 推断 `processing`。
- claim：ready 合并或单条；`overrideText` 优先。
- dispatch 失败：notify + ack（R3）。
- `POST /api/merge-batch/action`：send_now/split/edit。
- `POST /api/presentation-event`；`GET /api/poll-message` **404**。

## 四、客户端流程

pushMessage → MergeBatch → dispatch loop → claim → agent/launch → Presentation 出站。

## 五、接口

| 路径/函数 | 说明 |
|-----------|------|
| `/api/session-agent-phase` | Agent 阶段 |
| `/api/merge-batch/action` | 合并控制 |
| `/api/presentation-event` | Presentation |
| `/api/agent/launch|dispatch` | 转发 agent-api |
| `/api/stream-text` | 流式 |
| `performClaimAndMerge` | claim 合并 |

## 六、数据

`.qmsg/.claimed`；内存 `mergeBatchBySession`、`sessionAgentPhaseMap`、`sessionProgressMap`。

## 七、非功能与可观测

`dispatch_failed`、`presentation_failed`；节流 500–1500ms。

## 八、推送

SSE queue-update。
