# 消息队列与路由

## 一、能力范围

file-queue、sessionKey、ack、F1、**MergeBatch**、**Daemon dispatch**、SDK 流式 **final ack**、Presentation/stream 出站、SSE。

**不负责**：SDK Run 内部、CardKit 渲染（见 [02](./02-飞书通道.md)）。

## 二、设计决策与取舍

- 原子入队；`.qmsg→.claimed`；`ackOnReply` 删该 id 及更早项。
- **SDK final ack**：`doFlushStreamPost(final)` 传末条 inbound `message_id`；daemon `handleStreamText` final 时 `ackOnReply`。
- **resident dispatch**：每次传当次 `message_ids`；final 仅 ack 当次 batch 末条。
- **冷启动 orphan**：`cleanupOrphanClaimedOnColdStart` 将 stale `.claimed` 还原 `.qmsg`。
- **T7**：SSE/入队 → `scheduleAgentDispatch`(300ms) → agent-api；**无 poll**。
- **MergeBatch**：≥2 collecting → 静默 → ready → claim 合并；processing/静默期 defer dispatch。

## 三、服务端规则

- F1：`shouldSendEnqueueF1` suppress collecting 第 2+ 条；排队数仅 `getSessionUnclaimedCount`（`.qmsg`），**不含** orphan `.claimed`；`buildEnqueueStatusText` 在 `phase` 缺失时默认 `idle`，不用磁盘 `.claimed` 推断 `processing`。
- claim：ready 合并或单条；`overrideText` 优先。
- dispatch 失败：notify + ack 末条 `message_id`（R3）。
- **stream-text**：中间包不 ack；`final` 飞书先 `closeStreamingCardMode` 再 ack/stop（可选 `message_id`→`ackOnReply`）。CardKit 首包写 `cardId`/`elementId`/`cardSequence`/`streamCardKitMode`，更新递增 sequence，失败置 `streamCardKitMode=false` 走 PATCH/分段；SDK `streamPostChain` 串行防并发首包。
- **dispatch 传 ids**：`dispatchSessionToAgent` claim 得 `message_ids`，经 `forwardElectronAgentApi` 传 `/api/agent/launch`；`/api/agent/dispatch` 亦转发 `message_ids` 至 Electron agent-api。
- `POST /api/merge-batch/action`：send_now/split/edit。
- `POST /api/presentation-event`；`GET /api/poll-message` **404**。

## 四、客户端流程

pushMessage → MergeBatch → dispatch loop → claim（`message_ids`）→ agent/launch|dispatch → SDK 流式 → final stream-text（`message_id`=末条 inbound）→ daemon `ackOnReply` → Presentation 出站。

## 五、接口

| 路径/函数 | 说明 |
|-----------|------|
| `/api/session-agent-phase` | Agent 阶段 |
| `/api/merge-batch/action` | 合并控制 |
| `/api/presentation-event` | Presentation |
| `/api/agent/launch|dispatch` | 转发 agent-api；可选 `message_ids`（当次 claim） |
| `/api/stream-text` | 流式；飞书 CardKit 首选；`final` 关 streaming + 可选 `message_id` ack |
| `performClaimAndMerge` | claim 合并 |

## 六、数据

`.qmsg/.claimed`；`mergeBatchBySession`、`sessionAgentPhaseMap`、`sessionProgressMap`（CardKit：`cardId`/`elementId`/`cardSequence`/`streamCardKitMode`；fallback：`streamPatchMode` 等）。

## 七、非功能与可观测

`dispatch_failed`、`presentation_failed`；节流 500–1500ms。

## 八、推送

SSE queue-update。

## 九、已知限制与 TODO

按钮回调 T8；dispatch 不 re-queue；任务 launch 仍走 Electron。
